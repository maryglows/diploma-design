# Один проект Codex и постоянный контекст диплома

Обновлено 24.10.2026. Инструкция относится к проекту в **Codex**, не к разделу «Проекты» ChatGPT. Название `Diplom-design` в боковой панели само по себе не доказывает связь с репозиторием.

## Что должно быть связано

Проект Codex → рабочая папка репозитория (для локальной работы) либо выбранная облачная среда → `maryglows/diploma-design` в GitHub.

Внутри репозитория `AGENTS.md` задаёт постоянные правила: прочитать текущее состояние и задачи, выполнить доступную работу и сохранить контекст. Новому чату не нужно заново перечислять эти файлы, если он действительно запущен в этом репозитории и получил инструкции.

Ветка — версия работы внутри репозитория. Она не является способом постоянного подключения интерфейса к GitHub. Разные ветки могут содержать разный набор материалов.

## Однократная проверка проекта в Codex

Открой существующий `Diplom-design` и проверь его рабочую папку или выбранную облачную среду. Названия пунктов и место выбора зависят от версии Codex; из этого чата нельзя изменить настройки другого открытого проекта.

Для локального режима нужна папка **клона Git-репозитория**, а не только распакованный ZIP с PDF. В ней должны быть `AGENTS.md`, `CURRENT.md`, `TASKS.md` и Git-метаданные. Если такой папки на компьютере нет, можно клонировать репозиторий через GitHub Desktop и открыть полученную папку в Codex. В GitHub Desktop операция называется File → Clone repository; адрес: `https://github.com/maryglows/diploma-design.git`. Доступ к private-репозиторию должен быть предоставлен используемому GitHub-аккаунту.

Для облачного режима выбери среду с репозиторием `maryglows/diploma-design`; локальную папку на компьютере для этого создавать не нужно. Файлы в этой среде не обязаны совпадать с локальным checkout до синхронизации.

В новом чате выбранного проекта достаточно один раз попросить:

> Проверь, что этот проект открыт на maryglows/diploma-design и что ты получил инструкции AGENTS.md. Назови текущую ветку и ближайшую задачу из CURRENT.md и TASKS.md.

Это проверка настройки, а не обязательный стартовый текст для каждого чата. При корректной привязке дальше можно писать короткие поручения.

Проверка агентом: определить Git-корень; безопасно проверить имя репозитория по remote без вывода учётных данных; прочитать AGENTS.md и ссылки; установить фактическую ветку. Не печатать токены или содержимое файлов с учётными данными. Название проекта в панели не заменяет эту проверку.

## Какие ветки содержат наши материалы

При read-only проверке 24.10.2026 `main` указывала на коммит `63ef3ef`, а `research/users-movements-2026-10-22` — на `eb41dff`. Последний содержит промежуточные листы, презентацию и исследования. На этот момент main ещё не содержала коммит с ними.

Материалы предложены к включению в main через [PR № 1](https://github.com/maryglows/diploma-design/pull/1). Автоматически объединять его нельзя. Пока изменения не приняты в main, для продолжения на их основе нужно использовать содержащую их ветку. После одобрения автором и объединения PR следует обновить checkout; будущие задачи могут начинаться из актуальной main. Не нужно навсегда закреплять дату в имени рабочей ветки.

Эта проверка — снимок состояния, а не обещание, что ветки никогда не изменятся. Будущие чаты проверяют актуальное состояние.

## Как устроен перенос контекста

| Файл | Для чего нужен |
|---|---|
| [AGENTS.md](../../AGENTS.md) | Правила работы и порядок начала новой задачи |
| [PROJECT.md](../../docs/PROJECT.md) | Идея и ограничения диплома |
| [CURRENT.md](../../docs/CURRENT.md) | Текущий этап, результаты, препятствия, ближайшие действия |
| [TASKS.md](../../docs/TASKS.md) | Единственный список задач со статусами |
| [DECISIONS.md](../../docs/DECISIONS.md) | Принятые решения и их основания |
| [outputs/current/README.md](../../outputs/current/README.md) | Указатель текущих листов, презентаций и инструкций |

После содержательной работы агент обновляет эти записи по необходимости. Новый чат читает их сам. Решение, оставшееся только в переписке и не перенесённое в файлы, может не попасть в следующий чат. Полный текст всех разговоров автоматически не восстанавливается.

## Как писать после настройки

- «Продолжаем диплом. Возьми ближайшую доступную задачу».
- «Сегодня работаем над первым исследовательским листом».
- «Добавь мои замеры и пересобери второй лист».

Ссылку на GitHub и полный список файлов каждый раз повторять не нужно, если чат открыт в правильно настроенном проекте. Новые исходные данные — например замеры или новая консультация — передавать всё равно необходимо.

## Что GitHub не синхронизирует сам

Редактирование файла в Codex не равно публикации в GitHub. Для удалённого сохранения нужны коммит и успешная отправка ветки; для принятия в main — отдельное одобренное объединение. При переносе на другую машину требуется получить соответствующую версию репозитория. По текущей договорённости main без поручения автора не объединяем.

Репозиторий также не включает редактор PPTX в правой панели. Возможность просмотра и совместной правки определяется интерфейсом Codex и форматом файла; редактируемые исходники сохраняем независимо от наличия такой панели.
